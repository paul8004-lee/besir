## 2. 결정 (착수 승인에서 확정 — 2026-10-06)

운영자가 착수 승인에서 정했다. 0.1.x에서 게이트 표식으로 열어 둔 여섯 결정이 모두 닫혔고, 이 절은 **확정안과 버려진 안**의 기록이다. 결정에 기대던 절(spec REQ-002·009·011·012·013·014, acceptance AC-002·005·008·009·010·011, 이 문서 §1·§3·§4·§5·§7·§9·§10)은 확정안 하나만 남기고 다시 썼다. 출처: **D-1은 운영자가 작성자의 권장안과 다르게 골랐다** — 〔확정〕이지 〔제안〕이 아니다. D-2~D-6은 작성자의 권장안 (a)를 운영자가 그대로 받았다.

### D-1 — 조회 경로(식사 추천 기준 장소·이동시간 조회)도 묻는가 → **(b) 조회도 카드** 〔확정 — 운영자 선택〕

버려진 안: (a) 카드 없이 후보 목록의 첫 항목을 쓰고 결과 문구에 이름을 찍는다(작성자 권장안) · (c) 카드 없이 후보 이름을 모델에게 돌려주고 모델이 문장으로 묻는다(카드로 옮겨 온 실패 모양 — SPEC-UIKIT-008 AC-009 7번).

〔조사〕 조회 둘은 `resolveDestination`(`:2703`·`:2765`)과 `resolveOrigin`(`:2762`)이 unclear를 첫 후보로 평탄화했다. 확정 (b)의 구현 모양은 아래이고, 전부 〔조사〕(코드를 읽고 정한 것)이며 운영자는 "조회도 카드"만 정했다.

| 자리 | 모양 |

### D-2 — 후보 순서 → **(a) 제공자 순서 그대로** 〔확정〕

완전 중복만 이름+좌표 키로 지우고 5건 상한을 둔다. 앱에 낱말 판정이 남지 않아 `searchTopClearlyMatches`·`normalizedPlaceWord`가 죽는다(D-5). '스타벅스 홍대점'처럼 제공자가 엉뚱한 결과를 먼저 주면 그 결과가 맨 앞이고, 사용자가 카드에서 질의를 고친다(운영자 ⑤ "카카오맵과 같다"). 버려진 안: (b) 낱말 만족 결과를 앞당긴다 — 앱이 제공자 순서를 다시 매기는 보강이 남는다(⑤의 취지와 충돌).

### D-3 — 문안 → **(a) §4 제안 원문 그대로, 수정 카드 맥락 줄 포함** 〔확정〕

버려진 안: (b) 운영자가 고친 원문 · (c) 맥락 줄 없이. 이 결정으로 AI-18 (b)(수정 카드의 맥락 줄 단언)가 살아 남았다. **한 가지 파생**: 조회 도구의 동사(`조회하지`)와 줄 이름 `기준 장소`는 운영자가 본 원문에 없던 말이다 — 원문의 동사 자리·선언 설명(`:1635`)을 그대로 쓴 꼴이라 〔확정〕 범위의 연장으로 보았고, §4 끝에 따로 표시했다. 착수 설명에서 한 줄로 다시 보여야 한다.

### D-4 — 반복 점심을 어디서 묻는가 → **(a) 머무는 갈래를 지난 뒤 첫 저장 직전에 따로** 〔확정〕

머무는 두 갈래(`:2184-2188`·`:2195-2199`)를 지난 뒤, 첫 저장(`:2202`) 직전에 점심을 해석한다. 점심 시각 둘이 다 읽힐 때만 검색한다(지금 조건 `:2242-2243`과 같게). 쓰이지 않을 점심 줄이 뜨지 않는다. 출발지·목적지도 검색으로 푸는 요청이면 카드가 **두 장 차례로** 뜬다(출발지·목적지 → 확인 → 점심) — 둘째 카드도 아무것도 저장하기 전이다. 버려진 안: (b) 문자열 머무는 신호가 없으면 점심을 출발지·목적지와 한 카드에 모은다(좌표만 같은 머무는 반복에서 쓰이지 않을 점심 줄이 뜬다).

### D-5 — 죽은 코드 삭제 → **(a) 삭제** 〔확정〕

삭제 대상: `searchTopClearlyMatches`·`normalizedPlaceWord`·`drvTopMatches`와 단언 8건(AA-1 6 · AB-H04 2), 그리고 D-1 (b)로 호출처가 0이 된 `resolveDestination`(`creation` 기본값 매개변수 포함)·`resolveOrigin`. 단언을 지운 뒤 쓰이지 않는 바인딩 `let aaT = fresh()`(`Tools/GuardDriver.swift:1895`)·`let h4 = fresh()`(`:2280`)도 지운다. U-4 관측 두 사례('스타벅스 홍대점'→대학로점, '강남'→선릉과정릉)의 회귀선은 술어가 아니라 판정 수준에서 남는다 — AI-8(유지)과 AI-14(신설)가 "어떤 단일 결과도 묻는다"를 잰다. 버려진 안: (b) 남긴다 — 호출처 없는 함수가 남는다.

### D-6 — Tier와 파일 수 → **(a) Tier M · 크게 고치는 파일 2** 〔확정〕

`Shared/AIAssistant.swift`·`Tools/GuardDriver.swift`. 산출물은 다섯 파일(spec·plan·acceptance·research·progress), plan 감사 통과선 Tier M 0.80, 한 Day 파일 한도(3~4) 안.

### 결정표 밖 — 같은 대화에서 원래 질의를 다시 말하면 → **의도된 동작으로 둔다** 〔확정〕

확정 사전의 열쇠가 고른 장소의 이름이라 '스타벅스 강남점'을 다시 말하면 다시 묻는다. 운영자가 이것을 바꾸지 않기로 했다 — 원래 질의 열쇠를 사전에 함께 두는 별도 결정은 만들지 않는다(spec §3 마지막 줄).

**잔여 위험**

- 실제 카카오 목록의 모양·순서는 아무도 보지 않았다(키는 Worker 시크릿). 운영자 관찰("스타벅스 홍대점 → 안 뜨다 대학로점")이 유일한 실관측이다.
- 검색으로 푸는 장소마다 카드가 선다 — 한 턴 여러 호출에서 t32 증상이 더 자주 보인다.
- **카드 장수가 는다**(감사 1회차 A-2). 생성 세 도구는 `mode_this_time`·`buffer_minutes`·`notify_lead_minutes`·(반복의) `weeks`를 선언하지 않아 발화 파서(`statedArguments` `:349-355` — `지하철로`·`여유 N분`·`알림 N분 전` 같은 꼴만)나 실행 전 카드로만 채워진다. 단발 등록(`create_schedule`)의 제목도 프롬프트가 비우라고 지시해(`:1463`) [제목] 줄로 묻는다(`:505`). 그래서 그 값들을 말하지 않은 등록은 실행 전 카드가 먼저 서고, 검색 장소가 있으면 그 뒤 후보 카드가 선다 — 단발 등록은 **두 장**(지금은 정확·유일 일치면 한 장). 반복 + 점심은 실행 전 카드([반복 기간] — `weeks`는 발화로 줄 수 없다) → 출발지·목적지 후보 카드 → [점심 장소] 카드로 **최대 세 장**(D-4 (a)). 장수는 코드 읽기 가설이고 S-1·S-8이 처음 관측한다.
- **조회가 두 단계가 된다**(D-1 (b)): 이동시간 한 번 묻는 데 카드를 거치고, 식사 추천은 기준 장소를 검색으로 풀면 카드 → 답이다. 조회 도구에는 실행 전 카드가 없어 카드는 한 장뿐이다(줄 최대 둘 — 이동시간 출발지·목적지). 운영자가 정한 비용이다.
- **확인 경로가 조회 도구를 실행하는 첫 사례**다 — 드라이버(AI-21·22)는 도구 실행과 결과 문구 앞머리까지만 보고, 확인 뒤 모델이 조회 결과를 어떻게 말하는지(고른 장소 이름을 답에 쓰는지)는 시뮬레이터 S-11·S-12가 처음 관측한다.
- 조회 문구(`조회하지`·`기준 장소`)는 운영자가 본 원문 밖에서 파생됐다(§4) — 착수 설명에서 한 줄로 알린다.

## 9. 착수 전 설명 재료 (리드가 운영자에게 보일 것)

예시 목록은 **설명용**이다. 실제 카카오가 주는 목록은 이 레인이 보지 못했다 — 운영자 관찰과 드라이버 픽스처에서 모양을 빌렸다.

**카드가 몇 장 뜨는가** 〔조사 — 코드 읽기 가설, 실행 확인 전〕: 아래 예의 카드는 **후보 카드**만 그렸다. 이동수단·도착 여유·알림을 발화에 파서가 잡는 꼴(`지하철로`·`여유 10분`·`알림 10분 전` — `statedArguments` `:349-355`)로 말하지 않으면, 그 값을 묻는 **실행 전 카드가 먼저** 선다(생성 세 도구는 이 값들을 선언하지 않아 카드로만 채운다). **제목도 그렇다**(감사 2회차 N-1): 시스템 프롬프트가 "목적지·제목도 … 말하지 않았으면 비워둬라"고 지시하고(`:1463`) `create_schedule`은 제목이 비면 [제목] 줄을 세운다(`:505`) — 제목을 말하지 않은 단발 등록은 [제목]이 든 실행 전 카드가 먼저 선다. 그러니 단발 등록은 실행 전 카드 → 후보 카드로 두 장, 반복 + 점심은 [반복 기간] 실행 전 카드(기간은 발화로 줄 수 없다) → (출발지·목적지도 검색 질의면) 후보 카드 → [점심 장소] 카드로 최대 세 장이다. 지금은 정확·유일 일치면 후보 카드가 없어 한 장이 줄었다. 조회 도구(이동시간·식사 추천)는 실행 전 카드가 없어(`askFields`의 `default: break` `:635`) 카드가 한 장 — 검색 질의가 있으면 후보 카드뿐이다. 시뮬레이터 스크립트는 파서가 잡는 꼴로 입력해 실행 전 카드를 줄였다(`acceptance.md` 스크립트 머리).
