# SPEC-UIKIT-002 — acceptance.md

계획 SPEC이므로 전 AC를 ⬜(미확인)로 시작한다.

본 SPEC은 **전환**이다 — t1(순수 추출)이 "아무것도 안 바뀜"을 보였다면, 이쪽은 **바뀌는 것은
의도한 것뿐이고, 의도하지 않은 것은 하나도 안 바뀜**을 보인다. 그래서 어포던스 대조(AC-006)가
문서의 중심이고 절 단위를 일괄 통과시키는 경로가 없다.

카드 렌더링·제스처·접근성 낭독은 가드 밖이다(드라이버는 SwiftUI 뷰를 컴파일 대상으로 삼지
않는다). **AC-009(시뮬레이터·실기기)가 대체 불가능한 증거**이며 "드라이버 초록"으로 갈음하지
않는다 — 88/88 초록 다음 날 실기기 결함 7건이 나온 이력이 있다.

## AC-001 — 컴포넌트 표면 확장이 기존 호출부를 한 줄도 흔들지 않는다 ⬜

- **Given** `EditCardView`의 유일한 호출부가 `AIChatView.swift:106`이고, `AIAssistant`가 필드
  팩토리에서 `.init(key:)` **11회**·`Option` 생성 **16회**를 쓰고 있으며(실측, spec.md §1.1)
- **When** `Kind.toggle`·`Option.detail`·`EditField.busy`·`startsOpen`·`EditCardChrome`이
  (전부 기본값을 갖는 형태로) 추가되면
- **Then** 네 가지가 동시에 성립한다:
  1. `git diff origin/master...HEAD -- Shared/AIChatView.swift`가 **빈 diff**다 — 유일한 기존
     호출부가 무변경이다(REQ-004의 기본값 크롬).
  2. `grep -c '.init(key:' Shared/AIAssistant.swift`가 여전히 **11**, Option 생성(`Option(` +
     `.init(label:` 합)이 여전히 **16** — 팩토리가 줄어들거나 늘지 않는다.
  3. 토글 줄은 `chosen: "true"`/`"false"`로 seed된 형태로만 생성된다 — seed 없는 토글 필드를
     만드는 경로가 있으면 `isReady`(`EditCard.swift:145`)가 영원히 풀리지 않는다.
  4. 드라이버가 초록이다 — `Kind`를 망라 `switch`로 쓰는 곳이 없어(실측, 비교 6곳뿐) `case toggle`
     추가로 깨지지 않는다. 드라이버 **본문**이 바뀌어 있으면 REQ-041 위반의 신호다.

## AC-002 — 디바운서가 정확히 한 곳에 산다 ⬜

- **Given** 지연(350ms)·취소·같은 질의 스킵의 정책이 `AIAssistant.searchPlaces`
  (`:764-785`)에만 있고 `350_000_000`이 `Shared/`에서 1곳(`AIAssistant.swift:775`)이며
- **When** 정책이 값 타입 하나로 `Shared/EditCard.swift`로 옮겨지면
- **Then**
  1. `grep -rc "350_000_000" Shared/` 합이 **1**, 소재가 `EditCard.swift` — 2가 되면 복제고
     `AIAssistant.swift`에 남아 있으면 옮기지 않은 것이다.
  2. 지연·취소·스킵의 **셋 전부**가 그 타입 안에 있다 — 하나만 옮기고 나머지를 두 벌로

  3. `grep -c '^import SwiftUI' Shared/EditCard.swift` = **0** 유지 — 드라이버 컴파일 집합의
     SwiftUI-free 경계(REQ-040, t1이 세운 제약).
  4. `setLookup` 호출(`:769`·`:773`·`:782`)과 `maxPlaceSuggestions`(선언 `:755`·사용 `:783`)은
     `AIAssistant.swift`에 그대로 있다 — AI 쪽 의미는 따라가지 않는다(REQ-010 절).

## AC-004 — 카드가 폼 입력의 단일 출처가 된다 ⬜

- **Given** 폼 입력이 `@State` **11개**(`:13-37`)와 `canSave`(`:378-380`)로 흩어져 있고
- **When** 전환이 끝나면
- **Then**
  1. `grep -c '@State' Shared/AddEventView.swift`가 폼 입력을 전부 제거한 뒤의 수 — `card`·
     `confirmedPlaces`·`editing` 계열 로드 상태·`saving`·`estimating` 등 **화면 소유 상태만**
     남는다. `title`·`originPlace`·`query`·`arrivalDate`·`anchor`·`mode`·`bufferMinutes` 등
     폼 값의 `@State` 선언이 하나라도 남으면 이중 출처다.
  2. `grep -n 'canSave' Shared/AddEventView.swift`가 **0건** — 제출 판정은 `card.isReady`뿐이다.
  3. 카드 생성은 `.task`에서 **정확히 한 번** — `EditCardView(` 호출부가 `ScrollView` 루트의
     고정 위치에 있고 `Group`·`AnyView`·가변 `.id(...)`로 감싸지 않았다(REQ-021 (a)·(b)).
     `EditField.id`는 인스턴스마다 새로生겨(`EditCard.swift:65`) 지역 상태 다섯이 그 UUID를
     키로 쓰므로(`EditCardView.swift:344`·`:355`·`:365-366`), 매 렌더 재생성이면 장소 이름을
     칠 수 없다.
  4. `location.isLocating`·`estimating`이 `.onChange`로 해당 줄의 `busy`에 명시적으로
     연결돼 있다(REQ-021 (c)) — 잊으면 진행 표시가 안 뜨는 조용한 실패다.
  5. 장소 좌표는 선택 시각에 `confirmedPlaces`에 **즉시** 채운다 — 지연 해석 함수를 만들지
     않는다(REQ-020, `AIAssistant.swift:49`·`:748`과 같은 형태).

## AC-005 — 카드 밖의 것은 카드가 못 가지는 것만 남는다 ⬜

- **Given** 화면이 header(`:78-85`)·footer(`:362-376`)·`ConflictBanner`(`:281-286`)를 갖고
- **When** 전환이 끝나면
  1. header·footer는 원본 그대로 남고 카드 쪽 크롬은 `EditCardChrome`(빈 헤더·빈 확인)으로
     꺼져 있다 — 제목 둘·제출 버튼 둘이 되지 않는다(REQ-004·REQ-022 (a)).
  2. 조건부 줄 세 갈래가 계획대로다(REQ-022 (b)): `syncToCalendar`는 카드 **생성 시** 정적으로
     있거나 없다, `notifyLeadMinutes`는 토글 `chooseValue`에서 배열에 넣고 빼며 마지막 값을
     화면이 들고 재seed한다, `bufferMinutes`는 **아무 처리도 하지 않는다**
     (`departureAnchored` `EditCardView.swift:61-64`·`:119-126`이 이미 흐림+캡션을 붙인다).
  3. `ConflictBanner`는 화면 소유로 남고 시각 해석은 `BesirTime.parseDatetime`
     (`EditCard.swift:35-42`)을 지난다(REQ-022 (c)).
  4. `grep -c "DateFormatter()" Shared/AddEventView.swift` = **0** — `depFmt`(`:382-385`)가
     사라지고 같은 패턴이 `BesirTime`의 `static let`(이름 `compact`)로 옮겨갔다(REQ-023).
     **`when`으로 흡수하지 않는다** — 실측 재현(swift): `"M/d (E) a h시 mm분"`은
     `9/17 (목) 오후 3시 05분`, `when`은 `9월 17일 (목) 오후 3시 5분`이라 배너(`:548`)가 두
     문자열을 `~`로 잇는 폭이 늘어 줄바꿈이 깨진다.
  5. 재계산 버튼이 **글자 라벨**을 얻는다(REQ-022 (d)) — 원본 `:307-309`은 `Image` + `.help`
     (macOS 툴팁)뿐이라 iOS VoiceOver에서 이름이 없었다.

## AC-008 — 범위 경계와 품질 게이트 ⬜

- **Given** 본 SPEC의 변경이 4파일 안에서 일어난다고 못박았고
- **When** 구현이 끝나면
  1. `git diff --name-only --diff-filter=A origin/master...HEAD -- 'Shared/*.swift'`가
     **0건** — 새 소스 파일이 없으므로 `xcodegen generate`를 돌리지 않는다(**서명 리셋·Team
     재선택 요청이 없는 것이 통과 조건**, REQ-040 (d) — t1과 반대 방향의 기대).
  2. 바뀐 소스 파일은 `AddEventView.swift`·`EditCard.swift`·`EditCardView.swift`·
     `AIAssistant.swift` 4개뿐이다 — `EventDetailView`(t4)·`AddActivityView`·
     `ActivityDetailView`(t3)·`AIChatView`가 diff에 있으면 REQ-041 위반이다. 예외는 문서
     (루트 `plan.md`·본 SPEC 3종·`progress.md`)뿐이다. **드라이버 `Tools/GuardDriver.swift`도
     예외가 아니다** — 단언 추가 없음(AC-003)이므로 본문이 바뀔 이유가 없다.
  3. iOS·macOS 양쪽 **무경고** 빌드(툴체인 경고 제외), `cd proxy && npm test` 전체 통과.
  4. **D-3 기록 절**: 구현이 운영자의 결정을 반영했다 — (i)이면 폼이 AI 카드와 같이 과거를
     허용하는 것이 AC-009 시뮬레이터의 한 항목이 되고, (ii)였다면 REQ-041 예외 절이 spec.md에
     달려 있어야 한다(달려 있지 않은데 범위가 생겼으면 문서 누락이다).

## AC-009 — 시뮬레이터·실기기에서 전환된 폼이 온전하다 ⬜

드라이버가 못 보는 것의 목록. **시뮬레이터는 입력 문구 + 기대 결과를 정확히 준 스크립트
방식**(초기화 시점 포함)으로, 실기기는 사용자가 직접 확인한다. 사용자에게 넘기는 것은
**내가 검증할 수 없는 것만**이다.

시뮬레이터(내가 돌려 확인):
1. 새 일정 시트 → 카드가 뜨고 제목·목적지 줄이 열려 있다(`startsOpen`).
2. 장소 검색: 두 글자 이상 입력 후 멈춤 → **350ms 뒤** 후보 등장(기다림 없이 매 글자 호출
   안 됨). 같은 질의 재입력 → 재호출 없음(기존 결과 유지).
3. 즐겨찾기 칩 탭 → 즉시 확정(재검색 없음).
4. 시각 줄: 기준 칩 2개가 미선택으로 시작, 출발 기준 고르면 도착 여유 줄이 흐려지고 캡션.
5. 모드 칩 선택 → 소요시간이 칩 `detail`에, 출처가 줄 캡션에.
6. 알림 토글 끄기 → 리드 줄이 사라졌다가 켜면 마지막 값으로 돌아온다.
7. 캘린더 줄: 설정에 따라 있거나 없다(시트 열린 동안 바뀌지 않음).
8. 겹치는 일정 입력 → 배너 등장, 시각 표기가 `9/17 (목) 오후 3시 05분` 모양.
9. 빠진 값이 있으면 저장 비활성, 전부 채우면 저장 → 목록 등록.
10. 기존 일정 편집 → 값 전종이 카드에 로드된다.
11. (D-3 기본 (i)) 과거 시각으로 저장 → 일정은 만들어지고 알림은 예약되지 않는다
    (조용한 실패의 확인 — NotificationManager `:34` 거동).
12. 큰 글씨 최대 → 칩이 잘리지 않고 흐른다. 다크 모드 → 기기 설정을 따른다.

실기기(사용자 확인 목록 — 빌드로 검증 불가):
- 실제 출발 알림 수신(과거 시각 일정의 알림 **미수신** 포함).
- 칩 탭·검색 에디터 타이핑의 제스처 느낌 — 특히 `Stepper` 대체 경로(직접입력)의 불편 여부.
- VoiceOver: 줄 이름 + 사유 낭독, 토글 칩의 선택 발표, 재계산 버튼 이름, 배너 통째로 낭독.
- 캘린더 앱에 보이는 모습(등록·미연결 문구).
