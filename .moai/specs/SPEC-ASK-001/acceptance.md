## AC-001 — 얕은 메모리 제거 ✅

- **When** 본 SPEC 구현이 완료되면
- **Then** 툴은 9개가 되고, `ai_memory.json` 경로(`Shared/AIAssistant.swift:97`)·`factsBlock`/`prefsBlock`/`modeBlock`(`:485-489`)·`Config` 선호 필드(`Shared/Config.swift:29-33`)·`resolvedMode`/`resolveOrigin`의 저장값 폴백(`:757`·`:1810`)·`applyStatedPreferences`(`:321`)가 소스에서 사라진다. 빈 문자열→부재 처리는 유지된다.
- GuardDriver 단언 **(d)**: `toolsJSON()` 직렬화에 `remember_fact`·`forget_fact` 및 제거된 인자 부재. 유지 항목(빈 문자열 처리)은 기존 회귀 단언이 그대로 초록인지로 확인.
- ✅ 2026-09-15 관측(HEAD `b1771ae`): GuardDriver 88/88 — 단언 (d)(기억 툴·인자 부재)·(e)(툴 9개) 및 빈 문자열 처리 회귀 전부 초록.

## AC-002 — 묶음 카드 되묻기·1회 호출 ✅

- **Given** 생성 도구 호출에서 필수 인자가 하나 이상 비어 있고
- **When** 앱이 부재를 감지하면
- **Then** 채팅창에 인자별 칩 행을 가진 카드 1장이 뜨고(spec.md §4 승인 형태), 사용자가 확인 버튼을 누르면 수집된 모든 값이 실린 툴 호출이 정확히 1회 발생해 등록이 완료된다 — 그 사이에 모델이 임의 값을 채우는 경로는 존재하지 않는다.
- GuardDriver 단언 **(a)**·**(d)**.
- ✅ 2026-09-15 관측(HEAD `b1771ae`): GuardDriver 88/88 — REQ-020 카드 단언 (a)~(e) 19건 포함 전체 초록(부재 감지 → 카드 1장 → 확인 후 툴 호출 1회 경로).

## AC-003 — 카드 구성·직접입력·0분 칩·오버플로 ✅

- **Given** 이동수단·여유·알림이 한꺼번에 비어 있고(반복 일정이면 빈 인자가 5개 이상일 수 있다)
- **When** 카드가 뜨면
- **Then** 인자마다 행이 하나고(빈 인자 5개 → 행 5개), 모든 행에 `[직접입력]`이 있으며(빈 입력 제출 불가), `도착 여유`에는 진짜 `0분` 칩이 있다 — 발화로는 `v > 0`만 전달되므로(`Shared/AIAssistant.swift:1336-1341`) 카드가 0을 다시 설정 가능하게 한다. 카드가 길어지면 스크롤로 전체 행에 도달 가능하다(숨김 없음). 매번 물음이 유지된다 — 요청 사이에 기억되는 값은 없다(REQ-041).
- GuardDriver: 부재 인자 수 = 카드 행 수; 빈 직접입력 → 제출 거부.
- ✅ 2026-09-15 관측(HEAD `b1771ae`): GuardDriver 88/88 — 부재 인자 수=행 수·빈 직접입력 제출 거부·REQ-041 무기억 회귀 5건 초록.

## AC-004 — 발화 명시 값 우회 ✅

- **Given** 사용자 발화에 "자동차로 가자", "여유 20분" 같은 명시 값이 있고
- **When** 앱이 문장을 파싱하면
- **Then** 해당 값이 이번 요청의 인자로 채워지고 **그 인자의 카드 행은 만들어지지 않는다** — 카드는 진짜 모르는 것만 보여준다. 모두 명시돼 부재가 없으면 카드 없이 툴이 직접 실행된다. 값은 저장되지 않는다(REQ-040·REQ-041).
- GuardDriver 단언 **(b)**·**(c)**: 파싱된 값 반영 + 해당 행 부재; 빈 부재 집합 → 카드 0장·직접 실행.
- ✅ 2026-09-15 관측(HEAD `b1771ae`): GuardDriver 88/88 — 단언 (b)·(c)(명시 값의 행 부재·빈 부재 집합 직접 실행)·REQ-040/041 무기억 회귀 5건 초록.

## AC-005 — 결정적 검증 가능성 ✅

- **Given** 본 SPEC의 AC-001~004가 있고
- **When** `Tools/GuardDriver.swift`를 실행하면
- **Then** 단언 (a)~(e)가 모두 초록이고, 모델 호출·API 할당량 소모는 0회다. 모델 주도 대안(되묻기를 모델에 위임하는 설계)은 이 검증이 불가능했다 — 가드는 "되묻기가 사용자에게 닿았다"를 증명할 수 없다는 제약을 드라이버 머리말이 이미 문서화했다(`on_conflict`·`confirm_many`·반복 0 되묻기가 그 범주다).
- 완료 조건: 드라이버 전체 초록 — 신규 단언 (a)~(e) 전부 초록, 기존 단언에 빨강 없음. **총 단언 수는 인용하지 않는다**(동시 진행 중인 클램프 통일 `Store.clampBuffer`/`Store.clampNotifyLead` 작업이 단언을 추가하는 중 — 총수의 SSOT는 run-phase 실측).
- ✅ 2026-09-15 관측(HEAD `b1771ae`): GuardDriver 88/88 전체 초록 — 모델 호출 0회, 모델 없이 결정적 실행(CLAUDE.md 드라이버 계약).
