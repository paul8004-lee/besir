## 4. 정화(R1/E1/F2)와 앱 지시 재호출

토큰은 세 가지(`__current_location__` · `__no_outbound_leg__` · `__no_travel__`)이고, 앞뒤 공백을 벗겨 비교합니다.

| (도구, 키, 토큰) | 결과 |
|---|---|
| (create_recurring_schedule, origin_query, `__no_travel__`), 목적지 있음 | **목적지 값으로 교체**합니다(`:981` `replaced`, `:983` guard 통과). 교체 결과가 같은 값이라 머무는 카드가 **선택되지 않은 출발지 줄**을 다시 세웁니다(`:544-548`). `return_time`이 없으면 카드 대신 `stayingEndAsk`로 가고 등록하지 않습니다. |
| 위 조합, 목적지 없음 | 버립니다 → 머물지 않는 카드 |
| 그 밖의 모든 도구·키·토큰 | 버립니다(`:986-988`) |
| 토큰이 아닌 선언 키 / 문자열이 아닌 값 | 그대로 통과 |
| 선언 밖 키(weeks·mode 등) | 버립니다 |

- **사용자 선택 없이 실행부까지 살아남는 토큰은 0건입니다.**
  - 범위: 정화(`:965-993`), `fillStated`(`:1011`, 수단·여유·알림만 채움), `pendingAsk`/`isReady`
  - 실행부에 닿는 토큰은 모두 카드 선택이 정화 **뒤에** 얹은 값입니다.
  - 모델의 되울림만으로 머무는 반복이 확정되는 길은 없습니다. 교체는 출발지 = 목적지 값을 만들 뿐이고, 카드가 캡션(목적지 이름)과 '이동 없음' 칩을 달아 다시 묻습니다.
- **앱 지시 재호출** — 사용자 선택이 유지되지 않을 때는 모두 사실대로 다시 묻습니다.
  - `recurringArgumentIssue`, `stayingEndAsk`(`return_time`을 해석하지 못한 경우): '이동 없음'은 교체된 뒤 다시 묻고, weeks도 다시 묻습니다.
  - 현재 위치를 고른 뒤의 재호출: 토큰이 버려져 출발지를 다시 묻습니다.
  - `on_conflict`: O-3과 같습니다(출발지를 다시 물음).
  - `confirm_*`: 장소 토큰과 무관합니다.
  - 조용히 굳는 경우는 없습니다.
