## 4. code-safety 판정(읽기 전용 — 게이트는 재실측 없이 레인 측정치 인용)

**차단 0 / 비차단 4 — 있는 그대로 병합 가능.** 네 렌즈 전부 가동(0건을 찾은 렌즈도 무엇을 봤는지 서술):

- **await/인덱스**: 0건 — 새 await 주변에 획단 상태 없음, 토큰은 `let`으로 1회 획득해 페이지마다 OAuth 왕복이 붙지도 않음.
- **조용한 실패**: 신규 0건 — 제거된 삼킴 확인(5xx/429도 이전엔 빈 결과→와이프였는데 이제 throw), `json()` 내부 `try?`의 nil이 throw로 변환됨 확인, 드라이버 X2-0 catch는 빨간 단언으로 바꾼다.
- **외부 한도**: 1건 비차단 — 상수 `nextPageToken`을 서버가 계속 돌려주면 루프가 안 끝난다. 구글이 자기 페이지네이션 계약을 위반해야 하는 시나리오라 관측 사례 없음 — **페이지 상한 상설은 과잉 설계 판정**(발생 시 전경 수동 sync는 `isSyncing` 래치로 앱 재시작까지 차단, 백그라운드는 expirationHandler의 취소로 루프가 끊긴다).
- **복제된 계산**: 0건 — `nextPageToken`·`maxResults` 처리는 전 프로젝트 단일 출처(grep 확인).
- 특정 공격면: `fetchBesirItems`의 출구 전수 열거(빈 결과를 반환하는 실패 경로 없음), throw 시 무손상 확인, `collectPages` 격리 확인(호출처와 같은 MainActor 도메인), 드라이버 실코드 규율 확인(X1 판정 자체는 통신 클로저 안 인라인이라 드라이버가 닿지 않음 — 드라이버 주석도 이를 숨기지 않는다).

후속 카드 후보 2건:

1. `items` 캐스트가 깨진 200 응답(원소에 dict 아닌 타입 섞임 등)이 `:140`의 `as? … ?? []`에서 통째로 `[]`로 떨어져 "정말 빈 캘린더"와 구분 불가 — `page["items"]` 존재 판정 한 줄로 구분 가능. 현실성 매우 낮음.
2. (원하면) 중복 페이지 토큰 감지 또는 페이지 상한 — 위 무한루프 방어.

빌드 산출물: `build/Build/Products/Debug-iphonesimulator/besir.app` → `xcrun simctl install booted <경로>/besir.app`.

**사전(초기화 시점 — 여기서 초기화하지 않으면 옛 데이터로 결과가 무의미해진다)**

2. 앱 실행 → 설정에서 **구글 캘린더 연결**(로그인) — 이때 refresh token이 키체인에, 캐시 토큰이 메모리에 생긴다.
3. **이동 일정 2~3개를 만든다**(설정의 "일정 생성 시 구글 캘린더에 자동 등록" 켜짐 확인). 구글 캘린더 앱/웹에서 항목이 올라갔는지 확인.

**X1 — 오프라인 콜드스타트(핵심)**

4. 앱을 완전히 종료한다(앱 스위처에서 위로 밀기 — **메모리 캐시 토큰을 비우는 게 이 시나리오의 요건**).
5. 네트워크를 끊는다. 시뮬레이터에는 비행기 모드가 없으므로 **Mac의 Wi-Fi를 끄거나 케이블을 뽑는다**(실기기에서는 비행기 모드).
6. 앱을 다시 실행한다.
   - **기대**: 3)에서 만든 일정이 목록에 **그대로 전부** 보인다(사라지지 않는다). 알림 예약도 그대로. 이동시간 계산·AI 대화는 오프라인 실패 문구가 뜨는 게 정상(L10의 다른 항목).
   - **실패(결함 잔존)**: 일정이 사라지거나 알림이 취소되면 X1이 안 닫힌 것 — 보고 요망.
7. 네트워크를 복구하고 앱을 재실행한다 → 일정이 그대로 있고 sync가 정상으로 돌아오는지.

**X1 보조 — 정말 비운 캘린더(반대 계약, 순서 주의)**

8. 네트워크 켠 상태에서 구글 캘린더(웹/앱)에서 besir 항목을 **전부 삭제** → 앱에서 sync(재실행 또는 macOS 도구모음 버튼) → **기대**: 앱의 해당 일정도 사라진다(빈 결과는 "정말 비었다"로 동기화되어야 한다 — fail-closed가 빈 결과를 삼키면 안 되므로).
   8을 6보다 먼저 하면 6에서 확인할 일정이 이미 없다 — **4→6→7 다음에** 할 것.

**X2 — 250건 초과(선택, 부하 큼)**

26주 평일 반복+왕복 260건을 실제로 만드는 건 비용이 크다 — 이 루프는 드라이버 X2절(217/217에 포함)이 결정적으로 검증하므로 **실측은 생략 가능**. 하고 싶다면: 주중 반복 26주 이동 일정 1개를 왕복(가는 편+오는 편)으로 등록 → sync 후 **마지막 주** 일정까지 전부 목록·캘린더에 있는지.
